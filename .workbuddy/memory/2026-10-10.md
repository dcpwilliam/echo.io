## 新增「答案预测」接口（问题 → 最可能的 n 个答案 + 各自概率）

沿用既有分层与兜底约定（api → services → domain；echo/openai 双 provider；模型失败回落本地规则 + llmFallback 标记，接口永不 500）。

新增文件/改动：
- `app/domain/answers.py`：本地规则兜底 `hypothesize(question,n)`，概率衰减占位；`parse_probability` 兼容 0.62 / "62%" / 62。
- `app/prompts/templates.py`：新增 `hypothesize` 模板，指导 LLM 输出 `{"answers":[{answer,probability,reason}]}`。
- `app/services/answer_service.py`：`predict(question,n,use_llm,provider)`，含占位检测、脏概率清洗、归一化(sum≈1)、降序排名、n 夹紧 1~10、缺口补齐。
- `app/api/answers.py`：`POST /api/answers/predict`；`app/api/__init__.py` 已接线。
- `run.py` 自测新增该端点断言；README 已补文档。

验证：`run.py --selftest` 25/25 通过；mock openai provider 验证真实路径概率解析/归一化正确。
注意：echo provider 不认 hypothesize 任务，use_llm=True 且无 Key 时直接走规则不标 llmFallback（避免误判）。

## 新增后台管理页面（登录后使用，index.html 含测试台 tab）

需求：生成后台页面直接用 index.html，需登录后使用，管理页内加「测试台」tab。

新增/改动：
- `app/core/auth.py`：HMAC-SHA256 签名 token + HttpOnly cookie；账号密码来自 `AISERVICE_ADMIN_USER/PASS`（默认 admin/admin，启动告警）；`AISERVICE_SECRET`/`AISERVICE_SESSION_TTL`。`current_user(req)` 读 cookie/Bearer。
- `app/api/auth.py`：`POST /api/auth/login`（下发 Set-Cookie）、`POST /api/auth/logout`、`GET /api/auth/me`（401 未登录）。
- `app/core/server.py`：`_try_static` 处理 GET `/`(需登录,否则 302→/login) 与 `/login`(免登录)，从 `public/index.html` 提供；`_banner` 增加后台地址与默认密码告警。
- `public/index.html`：自包含管理后台，含 概览 / 测试台 / 接口清单 三个 tab；未登录显示登录框，登录后显示 dashboard。
- `app/api/__init__.py` 已加 auth 模块；`run.py` 自测加鉴权断言；README 补「后台管理页面」段与 env 表。

验证：`run.py --selftest` 29/29 通过；实测未登录 GET / → 302 /login，登录拿 cookie 后 GET / → 200 后台页（含「测试台」「接口清单」），错误密码登录 401，API 仍公开。
设计取舍：管理页强制登录，但底层 /api/* 业务接口保持公开（沿用小程序直连设计）；如需接口级鉴权可在 `_dispatch` 对前缀统一校验。

## 概览页加入 LLM Provider 动态管理（实时生效）

需求：在「概览」tab 加入 LLM provider 管理，可增删改 provider 信息并实时生效（无需重启）。

新增/改动：
- `app/llm/registry.py`（新）：provider 注册表，内存 + 落盘 `data/llm_providers.json`（原子写）。内置 echo（本地规则，不可删）与 openai（按 `LLM_*` 环境变量播种）。提供 list/get/create/update/delete/set_default，apiKey 脱敏、更新时空字符串保留原值、echo 拒绝删除、线程锁。
- `app/llm/__init__.py`：`get_provider(name)` 改为**每次按注册表现建实例**（去掉旧 `_cache`），`name` 缺省取 `registry.get_default_id()`；openai 兼容类型按注册表 baseUrl/apiKey/model/温度/最大token/超时/jsonMode/visionModel 构造，无 Key 或禁用回落 echo，并令 `provider.name=真实id`。新增 `get_active_provider_id()`。
- `app/llm/openai_compatible.py`：构造器支持逐 provider 覆盖项（temperature/max_tokens/json_mode/vision_model 实例属性覆盖 config 默认）；complete/describe_image 改用这些实例属性。`echo_provider.py` 加 `kind="echo"`；openai 加 `kind="openai"`。
- `app/services/answer_service.py` / `prompt_service.py`：用 `prov.kind != "openai" or not prov.available` 判断走规则兜底（替代旧 `pname != "openai"`），使自定义 id（非 "openai" 字符串）也能真正调用模型；analyze 也加早退兜底。
- `app/api/providers.py`（新）：`/api/admin/providers` 的 GET/POST/PUT/DELETE、`/{id}/default`、`/{id}/test`；全部 `_require_admin`（401 否则）。
- `app/api/__init__.py` 加 providers 模块；`app/api/health.py` 增 `activeProvider`/`providerCount`；`public/index.html` 概览页增「LLM Provider 管理」卡片（列表 + 新增/编辑表单 + 设为默认/测试/删除，apiKey 编辑留空=保留）。
- `run.py` 自测增 provider 断言（未登录→401、登录列表含 echo、新增、health 实时反映默认、更新、设默认、测试无 Key→no-api-key、删 echo→400、删除、回退 echo）；README 补 Provider 管理段与接口表，自测数 23→38。

验证：`run.py --selftest` 38/38 通过；离线校验 get_provider 解析自定义 provider（kind=openai available=True）与落盘；实跑服务端口 8128 确认登录→列表→新增→设默认后 `/health` activeProvider 即时切换（count=3）、test 真正尝试自定义端点（ok=False reason=error）、空 Key 更新保留、删除回退 echo。
